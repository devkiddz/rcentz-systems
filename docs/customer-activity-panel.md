# Customer activity panel

An authenticated island in the root layout makes customer tools available across public, account and dashboard routes. Anonymous/inactive accounts receive no customer feed. It does not extend to other Rcentz domains.

Desktop/tablet: bounded draggable panel, arrow-key repositioning through its grip, compact mode, and hide/reopen launcher. Detail panes open above/below the moved panel and reserve the header area. Mobile: full-width bottom quick menu with Workspace, Live chat, Messages, Notifications and Activities, with collapse/hide/reopen. Per-account browser storage saves position/display preference only; message content and credentials are not stored there.

GET /api/activity returns the authenticated account's latest 12 notifications, latest 12 project notifications, latest six member conversations and exact unread message/notification counters. Project activity uses existing PROJECT/PROJECT_UPDATE notifications generated by milestone/project changes. Those events are a subset of Notifications, so reading them reduces both corresponding counters. Internal-only href resolution and escaped React text protect links/content. The server never accepts a client-supplied account ID.

POST /api/activity marks at most 12 specified owned notifications read. Other accounts' IDs cannot change their read state. It shares the existing authenticated JSON/origin guard. GET /api/support/chat is read-only; POST reuses or creates the general support conversation using the existing rate limits, retry IDs and membership checks. On project-detail pages, the panel uses the existing project-scoped support route and conversation. The separate project launcher is removed.

Feeds refresh every 20 seconds while visible and after page/focus changes; open chat refreshes every five seconds. This is polling, not instant push, staff presence or automated support. Existing message and notification pages remain the full-history destinations. Replies depend on team availability.

No database schema changes, new services, real billing changes or new secrets. Validation includes production build/TypeScript, targeted ESLint, authenticated fixture tests for ownership/counts/CSRF/read state/read-only chat, and Chromium at 1440px, 768px and 390px in light/dark themes. Tests cover guest isolation, saved chat, counters, keyboard/pointer drag, collapse/hide/restore persistence, cross-page presence and logout cleanup.
